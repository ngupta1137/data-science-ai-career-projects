# Model card: retrieval and answering evaluation

Generated by `python -m rag_eval.report` from `results/metrics.json`. Do not edit by hand.

## Intended use
Learning. A reference for evaluating retrieval and answering separately, including refusal. Not a production question answering system.

## Data
41 generated documents and 110 questions about a fictional company (56 dev, 54 test, of which 38 answerable). See `data/DATA_CARD.md`.

## Design
Retriever settings and the headline retriever are chosen on dev questions only: BM25 k1 0.9, b 0.4; LSA 20 dimensions. The reader sees the top 3 documents. The abstention threshold is 0.000, chosen on dev.

## The traps, measured
- Threshold tuned on test: 0.481 versus 0.481 honest. The threshold was chosen on the questions it is scored on. Optimistic by construction.
- Never abstaining: 0.463 versus 0.481 with the dev threshold. A system that never abstains gets every unanswerable question wrong.
- Answerable questions only: 0.658 versus 0.481 on all questions. Scoring only answerable questions hides the cost of answering what should be refused.

## Limits
- The corpus is generated from templates about a fictional company. It teaches how to evaluate retrieval and answering. It says nothing about real documents.
- The test set is small (see test_questions), so every interval is wide. Differences of a few points are not evidence.
- Questions are written from the same templates as the documents, so lexical retrieval is easier here than on real text.
- The reader is a rule-based extractor, not a language model. LSA is a classical stand-in for dense retrieval, not a neural embedder.
- No language model generates or judges answers in this project. That comparison is designed, not built.
