# Model card: drift monitoring

Generated by `python -m drift_monitor.report` from `results/metrics.json`. Do not edit by hand.

## Intended use
Learning. A reference for choosing, calibrating, and testing drift monitors against drift whose start is known. Not a production monitoring system.

## Data
Simulated weekly batches of 500 rows over 52 weeks, drift starting at week 26. The monitored model is a logistic regression with reference AUC 0.816. 1000 null streams set thresholds, 100 streams per scenario picked the headline, and 300 streams per scenario were scored once. See `data/DATA_CARD.md`.

## Design
Each threshold is the 95% quantile of the weekly maximum of the statistic over null streams, so a null stream has about a 5% chance of any alarm in 52 weeks. Label-free monitors: psi_max (largest PSI over features), ks_max (largest KS over numeric features), score_psi (PSI of the model score). auc_drop uses labels that arrive 4 weeks late. The psi_fixed rows use PSI cutoffs as commonly quoted, with no calibration.

Thresholds:
- psi_max: 0.0668
- ks_max: 0.0939
- score_psi: 0.0594
- auc_drop: 0.0610

Headline chosen on dev (mean detection over feature-drift scenarios): psi_max 1.000, ks_max 0.802, score_psi 0.850. Headline: **psi_max**.

## Limits
- All data is simulated. Drift sizes and the model are assumptions, not measurements of a real system.
- Streams are independent weekly batches of 500 rows with one drift event. Real drift is messier and several things move at once.
- Monitors compare each week to a fixed reference. They do not adapt, retrain, or handle seasonality.
- The KS monitor covers numeric features only, so it cannot see the categorical shift. Part of the gap between PSI and KS is that design choice, not the statistics.
- Thresholds are calibrated for a 52 week horizon. A longer horizon needs a higher threshold for the same chance of any false alarm.
- Thresholds are calibrated to a 5% chance of any false alarm in a 52 week null stream. Choose your own budget for your own cost of a false alarm.
- The model is a logistic regression on five numeric features and one categorical feature. Monitor behaviour on high-dimensional or text inputs is not tested.
