# Model card: fraud detection

Generated by `python -m fraud_detection.report` from `results/metrics.json`. Do not edit by hand.

## Intended use
Learning. A reference for evaluating a rare-event classifier with ranking, calibration, and cost metrics. Not for deciding which real transactions to block.

## Data
Credit card transactions, 284,807 rows, 492 fraud (0.1727%). 1,081 duplicate rows kept. See `data/DATA_CARD.md`.

## Split
time-ordered: fit, then validation, then test. Fit 159,492 rows (356 fraud), validation 39,873 (28 fraud), test 85,442 (108 fraud, rate 0.1264%).

Brier raw 0.000441, sigmoid 0.000428, isotonic 0.000429, constant prevalence 0.001263. Sum of predicted over actual fraud: raw 0.98, sigmoid 0.91, isotonic 0.84 (1.00 is calibrated in the large). Calibrators are fitted on validation, which holds 28 fraud rows.

## The traps, measured
- Accuracy: always predicting legitimate scores 99.8736%. The model at its cost threshold scores 99.9286% and catches 75.9% of fraud.
- Tuning the threshold on test: cost 3,453 with a validation threshold versus 3,134 with a test threshold. The difference of 320 is optimism you cannot get in practice.
- Random split: PR-AUC 0.8788 on a random split against 0.7847 on the time split. The two test sets contain different rows, so this compares evaluation designs, not identical rows.

## Where it fails
Lowest recall amount band with at least 10 fraud rows: **amount_below_fit_median**. Overall recall of the policy: 37.0%. Full tables are in `results/error_analysis.json`.

## Limits
- The cost model is an assumption: a missed fraud costs its amount, a flag costs a fixed review cost. Real costs differ.
- The interval resamples rows as if independent. Transactions on one card are correlated, so the true uncertainty is wider.
- The test period is about one day of data. It cannot show how the model behaves over months of drift.
- The V1 to V28 features are PCA outputs computed on the whole dataset, including the test period, before this project saw them. That leak cannot be undone here.
- Duplicate rows are kept. The count is recorded in the data section of metrics.json.
- Hyperparameters, calibration, and the threshold all use the same validation split, so validation scores are optimistic. Test scores are not.
