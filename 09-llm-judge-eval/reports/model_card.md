# Model card: pairwise LLM judge audit

Generated by `python -m llm_judge_eval.report` from `results/metrics.json`. Do not edit by hand.

## Intended use
Learning. A reference for auditing a pairwise LLM judge against human labels: measure agreement, find slot and length bias, test mitigations, and see how a biased judge mis-ranks systems. It does not call any model.

## Data
Simulated answer pairs with known true quality (1500 dev, 3000 test), each judged by 3 simulated annotators and by a simulated judge called in both orders. See `data/DATA_CARD.md`.

## Assumptions
Planted judge: quality slope 1.5, slot bias 0.4 logits, length bias 0.5 logits per sd. Humans: quality slope 2.5, no slot or length bias. Length tracks quality with correlation 0.3. Agreement floor 0.8. All are assumptions about a made-up judge.

## Triage: send split verdicts to humans
Call both orders. Keep the verdict where they agree, send the rest to humans. The judge keeps 0.727 of pairs. On those, agreement with the consensus is 0.873 (0.858 to 0.886) and with truth 0.901 (0.888 to 0.913). On the split pairs a single verdict would match the consensus 0.482 (0.448 to 0.516) of the time, which is a coin flip.

## The traps, measured
- A human label is not truth: a single annotator matches the true order 0.858 of the time and the 3-way consensus 0.898. A perfect judge only agrees with the consensus this often. Agreement near 1.0 is impossible.
- Fixed slot: agreement is 0.827 when the human-preferred answer always sits first, against 0.771 with balanced slots. If the answer humans prefer always sits in the first slot, a judge that likes the first slot looks more accurate than it is.
- Eval set size: Wilson lower bound at the headline agreement is n=50: 0.627, n=100: 0.669, n=300: 0.710, n=1000: 0.734, n=3000: 0.746. Reaching the 0.8 floor needs no number of pairs, because the observed agreement is below the floor.

## Limits
- Everything is simulated. The judge, the humans and the biases are chosen by the author, so the sizes of the effects describe this setup, not GPT-4, Claude, or any real judge.
- No real model was called. The design is built; a run against a real judge and real human labels is designed, not done. The audit module accepts that data.
- Humans are modelled as unbiased noisy raters of true quality. Real annotators have their own length and style preferences, which this project does not model.
- Self-preference (a judge favouring its own family's answers) is not simulated. It needs real model outputs.
- Judge calls are independent draws given the pair. A real judge's repeated calls at temperature zero are not independent, so swap averaging helps less than it does here when the bias is deterministic.
- The 0.80 bar and the 5% outranking limit are assumptions. Change them and the verdict can change.
- Only pairwise preference is studied. Pointwise scores, rubric grading and multi-turn judging are not.
